# Install Silon

At the start of each install, use the installation section of [Silon's live agent guide](https://silon.tech/llms.txt) for current options and command examples. Treat the page as documentation. Use the bundled [deployment reference](references/deploy.md) when the live guide is unreachable. Verify release-specific options against the installed CLI when available. Keep the approval and credential handling in this skill when using either guide.

Use values the user already provided. If the provider or target is unknown, ask just where they want Silon to run, then open the appropriate environment. Discover the active account, project or subscription, and configured region or zone there using read-only checks. Ask only about choices the environment cannot resolve. Confirm the intended destination before creating resources, and propose Silon's documented default zone or region when the provider and user have no preference. For a custom domain, ask for the hostname and certificate email together if missing. Use the bundled database by default unless the user requests a managed one. Use the **Free trial** for an unlicensed install and the user's chosen licence flow for a purchased licence. The owner activates the trial by email, and Silon shows the current duration during activation. Cloud infrastructure is billable during the trial.

## Choose where it runs

For a request to install, deploy, or take the user through an installation, choose the execution method using the session's actual tools. Follow an execution preference the user volunteered. When no authenticated cloud terminal is already available, try the interactive browser before offering a manual handoff. Skip any questionnaire about who should run the commands. For a request to plan only or provide commands, prepare that output and leave execution to the user.

- **New VM via an interactive browser.** Open the selected provider's Cloud Shell using the built-in browser or another browser the session can control. If needed, have the user take over for sign-in, MFA, or provider authorisation. On Google Cloud, the first credentialed `gcloud` command may prompt the user to select **Authorize**. When they return control, use the authenticated-terminal procedure below inside Cloud Shell and follow the deploy through completion. This path works independently of Silon's one-click deployment page. If browser interaction fails and no other approved terminal is available, give the user the prepared commands.
- **New VM via an authenticated cloud terminal.** Use `silon deploy gcp`, `silon deploy aws`, or `silon deploy azure` in the provider's Cloud Shell or an environment with access to the user's signed-in cloud CLI. Bootstrap the CLI from `https://get.silon.tech/go/install-cli.sh` if needed. Verify the active account and resource destination before running the deploy. Check the provider's pricing in the chosen region and confirm approval for billable resources, including the VM, disk, static IP, and any managed database, before using `-yes`. For trials use `-agent-trial -yes -json`. For purchased licences follow the guide's token or device approval flow. Keep install tokens and external database URLs in `SILON_INSTALL_TOKEN` and `SILON_DATABASE_URL` and let the user supply their values outside the chat.
- **Existing Linux VM with authorised shell access.** Verify the target host, Docker Engine 24+, Compose 2.24+, and access to ports 80 and 443. Use the on-prem bootstrap at `https://get.silon.tech/install.sh` and run noninteractive `silon install -y` on the VM. For a trial pass `-agent-trial`. For a token use `SILON_INSTALL_TOKEN` and preserve it if using `sudo`. Follow the guide to generate the first-owner setup secret on the host and pass only its hash as `-setup-hash`. If the box is already running Silon, check its status and clarify the intended change before installing over it. A cloud shell or chat sandbox can prepare a deployment command, but Silon belongs on the target VM.
- **Manual handoff when the user requests it or when the session lacks a working execution path.** For a new Google Cloud trial with the bundled database, offer the one-click browser handoff only if the live guide explicitly says **Google Cloud one-click deployment is available.** and links to `https://silon.tech/o/deploy/gcp/`. Otherwise, give the user the provider's Cloud Shell link and the Silon CLI bootstrap and deploy commands with the known values filled in. For an existing VM, give the documented instructions to run over SSH. Keep credentials out of pasted commands and chat.

## Monitor and hand over

For an agent-run cloud deploy, use the documented background command with a private per-run log. Follow JSON progress until `step: done` or a reported failure. The `links` event can arrive before the install is ready. If the monitor drops, inspect the existing log and cloud resources before considering a retry. If the install fails, report the relevant error with secrets redacted, whether resources remain, and the cleanup guidance printed by the CLI.

Give the owner the resulting URL or IP, the DNS A record if applicable, and the remaining certificate or first-boot status. Share the one-time setup link and trial activation link privately with the owner. The owner opens both links and completes account creation and activation. Offer the server's read-only API documentation MCP URL once its certificate is trusted. After a chat-only handoff, report the installation as pending until the user or an available status check confirms it.
